# TraceForge: beginner-friendly developer guide

This guide is written for someone who is learning the codebase. You do not need React or frontend experience to run, test, or explain this project.

## 1. What the application does

TraceForge is a Python API that stores information about requests made to an AI application. A trace records the prompt, response, model/provider labels, latency, token counts and status. The API can list and search traces, calculate basic usage metrics, compare outputs against expected answers, and store prompt-template versions.

The current demo uses sample data. It does not call OpenAI, Anthropic or another model provider.

## 2. Tools used

| Tool | What it does here |
|---|---|
| Python | Main programming language |
| FastAPI | Defines HTTP endpoints and validates requests |
| Pydantic | Checks incoming JSON data |
| SQLAlchemy | Maps Python classes to database tables |
| SQLite | Local database; no separate database server needed |
| Pytest | Runs automated tests |
| Docker | Packages the API so it can run in a container |
| GitHub Actions | Runs tests when code is pushed |

## 3. Run it on your computer

Install Python 3.11 or newer. Open Terminal in the project folder.

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
uvicorn app.main:app --reload
```

### Windows PowerShell

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
uvicorn app.main:app --reload
```

Open http://127.0.0.1:8000/docs. This page is generated by FastAPI and lets you try the endpoints from a browser.

To stop the server, press Ctrl+C in the terminal.

## 4. Try the demo

In a second terminal, run:

```bash
curl -X POST http://127.0.0.1:8000/api/demo/seed
curl http://127.0.0.1:8000/api/traces
curl http://127.0.0.1:8000/api/metrics
```

The seed endpoint inserts four deterministic example traces. It only seeds an empty trace table; repeat calls do not add duplicate demo batches.

To create a trace yourself:

```bash
curl -X POST http://127.0.0.1:8000/api/traces \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "What is an API?",
    "response": "An API lets software systems communicate.",
    "provider": "demo",
    "model": "sample-model",
    "latency_ms": 85,
    "input_tokens": 10,
    "output_tokens": 9
  }'
```

## 5. Understand the folder structure

- `app/main.py`: HTTP routes. Start here to see what a client can request.
- `app/schemas.py`: accepted request fields and validation rules.
- `app/models.py`: database tables.
- `app/database.py`: database connection and session lifecycle.
- `app/evaluation.py`: scoring functions used by evaluation requests.
- `app/config.py`: environment-based configuration.
- `tests/`: automated checks of API behavior and scoring.
- `.github/workflows/ci.yml`: runs the test suite on pushes and pull requests.
- `docs/`: architecture, API notes and this learning guide.

## 6. Run the tests

```bash
python -m pip install -e '.[dev]'
python -m pytest
```

The API tests use a temporary in-memory SQLite database, so they do not need your demo database.

## 7. Explain the important ideas

**What is an API?** A set of defined routes that let another program exchange data with this service using HTTP.

**What is a trace?** One recorded interaction. It connects the prompt and response with metadata such as latency, token counts and status.

**What is an ORM?** SQLAlchemy maps Python classes to relational database tables, so application code can work with objects while SQLAlchemy generates SQL.

**What is Pydantic validation?** It checks incoming JSON before route logic runs. For example, a negative latency or an unsupported status is rejected with HTTP 422.

**What is an evaluation metric?** A repeatable rule for comparing an actual output with an expected output. Exact match checks equality after trimming whitespace and ignoring letter case. Normalized similarity uses Python's `difflib.SequenceMatcher`; it is lexical similarity, not AI understanding.

**What does the error rate mean?** The number of traces marked `error` divided by all stored traces. It is a simple aggregate over the records in this demo.

## 8. Be precise in interviews

You can say:

"I built a Python FastAPI service that records AI interaction traces in a SQL database, exposes endpoints to search traces and aggregate latency/token/error metrics, and stores evaluation results using exact-match and lexical similarity scoring. I added request validation, automated API tests, Docker setup and a GitHub Actions test workflow."

Do not claim that this release has a React dashboard, live LLM-provider integrations, semantic embeddings, distributed background workers, multi-tenant authentication or production deployment. Those are possible future improvements, not implemented features.

## 9. Suggested learning sequence

1. Run the service and explore `/docs`.
2. Read `app/schemas.py` and understand the validation rules.
3. Read one route in `app/main.py`, then find the model it saves in `app/models.py`.
4. Change a harmless validation limit and add a test for it.
5. Add one small API feature, write a test, run the full test suite, and push your change.

Make changes yourself and keep notes about what you learned. Being able to explain a smaller project honestly is more valuable than listing technologies you cannot discuss.
